# UI audit and Workshop / AI Lab build spec — 2026-09-30

Written after driving the real app, screen by screen. The owner's summary of what they saw: **Workshop and AI Lab
show things, but almost nothing in them can be used; they are information screens.** The audit confirms that, finds
what else is wrong, and turns "make them function" into a build list a cloud session can execute.

Screenshots are in [`docs/screenshots/2026-09-30/`](screenshots/2026-09-30/) (a cloud session cannot run this macOS
app, so look at them). They were taken before the icon fixes listed in section 2, so a few blank icons in them are
already fixed.

## 1. How this was done

- Built with `script/build_and_run.sh --verify` (Xcode 27.0, macOS 27.0.1, Apple M3 Pro, 18 GB). Window 1419x838.
- Real data, not `-mockData`: Alabama and Arizona packs installed, one RTL-SDR dongle attached (Generic RTL2832U,
  serial 00000001), live OpenMHz, Foundation Models and Private Cloud Compute both reporting available.
- Driven through the accessibility API and screenshots. Every sidebar screen was opened.
- **Not exercised** (say so rather than guess): starting the Scanner or either Air receiver (audio/antenna), MLX model
  downloads (multi-GB), Get Data, writing to a radio, Settings, the iOS and menu-bar targets, any over-the-air decode.

## 4. Workshop: what is wrong, and what it should be

### What is on screen today

`App/Shared/Views/WorkshopView.swift` renders: a hero with a decorative spectrum line and a "BENCH 2/2" gauge; four
metric cards; **eight navigation buttons that duplicate the sidebar**; then about 35 capability tiles in four sections
from `WorkshopCatalog` (`Packages/SignalHiveCore/.../Models/WorkshopCatalog.swift`).

### Findings

1. **Tiles report status but rarely act.** Only 13 of the ~35 tiles have a `destination`, and a destination only
   navigates. No tile can *fix* what it reports ("Needs setup: Open Browse and get a state's data" has no button;
   "Add a host in Scanner" has no button; "Needs libhackrf" has no help).
2. **Some destinations lie.** ACARS, AIS and Morse are "Not connected yet" and say "the app decodes nothing here", yet
   their tiles lead to the Scanner, which cannot decode them. P25/DMR, paging, FT8, every hardware tile except Network,
   and every Planned tile have no action at all.
3. **The decorative waveforms are fake data.** Each tile's ribbon is a hash-seeded constant
   (`WorkshopView.samples(for:)`) and the hero line is a fixed array. They look like live signal. That contradicts the
   app's own "truthful gates" rule. Remove them or feed them real data.
4. **The catalog is stale against the code.** The embedded driver package already ships ISM-sensor decoding
   (rtl_433-style, 433.92 MHz), **Meteor-M LRPT** image decoding, **RS41 radiosonde** decoding, an rtl_tcp server and an
   EEPROM tool, each with an `rtlsdr-tool` command (`Packages/SwiftRTLSDR/docs/DECODERS.md`). The Workshop lists LRPT as
   "Planned: needs QPSK demodulation" and does not mention ISM, radiosondes or the rtl_tcp server. None of them has had
   a live signal yet (the decoder doc says so); none is reachable from the app.
5. **Metrics do not mean anything.** "Sources 2" counts the Test Signal Generator. "Decoders 2" counts only ADS-B and
   UAT. "BENCH 2/2" divides (packs + sources) by a constant 6. `WorkshopCatalog.readiness(for:)` already computes a real
   ready/implemented ratio and is unused.
6. **Planned items sit on the home screen** (11 tiles of things that do not exist) and dilute the working ones.
7. **Air Map's demo sky is gone from the UI** (Codex removed the button in `80cdfc6`) while the catalog still says "A
   demo sky runs without hardware". Pick one (section 6).
8. Tile buttons have no accessibility label; tile heights jitter by ~10 pt between neighbours.

### What it should be

The Workshop is the **launchpad and readiness checklist**: every tile ends in a verb, and a tile that is not ready
offers the step that makes it ready.

**Core (testable in `SignalHiveCore`):** replace `destination: WorkshopDestination?` with an action.

```swift
public enum WorkshopAction: Equatable, Sendable {
    case open(WorkshopDestination)                 // go to a panel
    case launch(WorkshopDestination, WorkshopPreset) // go there and start something
    case fix(WorkshopFix)                          // do the setup step from the tile
    case learn(String)                             // explain a not-connected / planned item (sheet)
}
public enum WorkshopFix: Sendable { case getFCCData, addNetworkSource, usbHelp, installTool(String), downloadModel }
public enum WorkshopPreset: Equatable, Sendable {
    case scannerTune(mhz: Double, mode: String), listenADSB1090, listenUAT978, decoder(String)
}
```

Each item carries a primary button label (Open, Start listening, Get data, Fix, Details). Rules, enforced by
`WorkshopCatalogTests`:

- every `ready` or `needsSetup` item has an action; every `needsSetup` item has a `.fix`;
- a `notConnected` item never routes to a panel that cannot do the thing (it gets `.learn`, or the Decoder Hub once
  that exists);
- `planned` items are not in the home grid (move them behind a collapsed "Roadmap" disclosure).

**App:**

- Add a small router (an `@Observable` on `AppModel`) holding a pending `WorkshopPreset`. `ContentView` owns
  `selection`; Scanner, Air Map and the Decoder Hub consume the preset on appear (tune 162.550 NFM and start live scan;
  start the 1090 MHz receiver; open ACARS with its preset).
- Replace the eight-button grid with real **quick actions**: "Listen: NOAA weather", "Airband", "Track aircraft",
  "Get state data", "Open last codeplug", plus a **Recent** row (last tuned frequency, last codeplug, last system).
- Hero gauge = `WorkshopCatalog.readiness(for:)`. "Sources" excludes the test generator. Drop or truthfully feed the
  ribbons.
- Add the missing tiles (ISM sensors, Meteor LRPT, radiosondes, rtl_tcp server, EEPROM/serial provisioning) as
  `notConnected` with a `.learn` until the Decoder Hub wires them.
- `.fix(.getFCCData)` presents the existing `GetDataSheet`; `.fix(.addNetworkSource)` presents the Scanner's source
  sheet; `.fix(.usbHelp)` explains the dongle cannot be shared between programs.

### The Decoder Hub (new sidebar panel)

This is the single biggest "it shows up but does nothing" gap. `SignalDecoder` (`identifier`,
`requiredBandwidth`, `process(iq:sampleRate:) -> [DecodedMessage]`) already gives every decoder one interface, and
`ChannelDownconverter` plus `DSPPipeline.channelOffsetHz` can isolate a channel.

- A `DecoderSession` in `SignalHiveCore`: `SDRDevice` -> tune to a preset -> channelize -> `decoder.process` -> async
  stream of messages, with messages/minute, last-heard and start/stop. Headless tests feed it synthetic IQ
  (`MorseCodec.encodeIQ` exists; build equivalents for ACARS/AIS).
- View: decoder list on the left with presets (ACARS VHF airband, AIS 161.975/162.025 MHz, ISM 433.92 MHz,
  radiosondes 400-406 MHz, Meteor LRPT 137.1/137.9 MHz, POCSAG/FLEX, NOAA APT; verify each frequency before shipping),
  live message table on the right (time, raw, parsed fields), copy/export, "save frequency to codeplug".
- Order: Morse/CW and ACARS (pure Swift, simplest), AIS (also feeds the AI pattern-of-life alerts), ISM (driver
  decoder), radiosonde, then LRPT images. dsdccx / multimon-ng remain temporary adapters; hide their tiles when the
  tool is missing and offer the install instructions via `.fix(.installTool)`.
- ADS-B and UAT stay in Air Map / Air Data; the hub links to them.

## 5. AI Lab: what is wrong, and what it should be

### What is on screen today

`App/Shared/Views/AILabView.swift`: hero with a "5/12" gauge; four provider tiles; a 12-tile "Feature Map"; the MLX
download manager; a dev-facing "Implementation Path" panel. **The only controls in the entire screen are the MLX
Download / Cancel / Remove / Hub buttons.**

### Findings

1. **No AI feature can be invoked.** RF coach, Codeplug assistant, ADS-B/UAT briefing, Deep RF report, AIS alerts and
   the offline assistant are all status text.
2. **"Available" is a probe result, not a capability.** On-device Foundation and Private Cloud Compute both report
   available on this Mac, so three features say "Available", but nothing calls them. The "5/12" gauge counts those.
3. **The one engine that exists cannot be called.** `SignalDescriptionEngine.describe(classification:...)` takes a
   `ClassificationResult`, which only the Core ML classifier produces, and that model package is missing. It needs an
   overload that takes plain context (frequency, mode, FCC record, RSSI) and no classification.
4. **Downloaded models do nothing.** Downloads, resume and SHA-256 checks work (tested), but `mlxRuntimeAvailable` is
   hard-coded `false` and no inference runtime is linked.
5. **Core ML signal ID is blocked on an artifact that does not exist**: `AutoClassify_v2.mlpackage`, its benchmark and
   `accuracy_by_snr.json` (see `DSP/Models/AutoClassify_v2.manifest.json`). There is no training pipeline in the repo.
6. **No session memory exists**, so "Session reports" and "Deep RF report" have nothing to summarize.
7. UI: the use-case chips at the bottom of each feature tile are clipped ("Name unknown si…"); tiles are 276 pt tall
   with large empty areas; the roadmap panel is developer content on a user screen.
8. The AIS pattern-of-life engine (`PatternOfLifeEngine`) works but has no data source: AIS is not connected (see the
   Decoder Hub).

### What it should be

AI Lab becomes a **workbench of task-shaped tools, each with a working entry point in context**, not a catalog. Every
result shows which provider answered (Foundation on-device, PCC, MLX, or "rules"), what inputs it used, and the
latency. A deterministic rules answer is always available and is labelled as such. Nothing is sent off the Mac except
through PCC, and PCC is used only when the user picks it.

**Core (`SignalHiveCore/AI`, all testable with a fake provider):**

```swift
public protocol LanguageModelProvider: Sendable {
    var kind: AIProviderKind { get }
    func availability() async -> ProviderAvailability
    func respond(to request: AIRequest) -> AsyncThrowingStream<AIChunk, Error>
}
// Providers: FoundationOnDeviceProvider, PrivateCloudProvider, MLXProvider, RulesProvider (deterministic, always on)
public struct AIRequest: Sendable { var task: AITask; var context: AIContext; var preferred: AIProviderKind? }
public enum AITask: Sendable { case explainSignal, explainLicense, reviewCodeplug, briefAviation, sessionReport, ask(String) }
```

`AIContext` is a plain value assembled by the caller (frequency, mode, RSSI, `FrequencyDetail`, codeplug channels,
`AviationPicture`, session events). `AIRouter` picks the provider (automatic order: on-device, PCC if opted in, MLX if
a model is installed, rules) and always appends the rules answer's facts so the AI cannot contradict them.

**Build order, each item usable on its own:**

1. **Explain** (RF coach). An "Explain" button on `FrequencyDetailView`, on each Scanner activity row and on Trunked
   talkgroups opens an Explain sheet prefilled from that context. Foundation Models with `@Generable` output
   (summary, likely service, suggested demod, safety note, next actions), streamed; rules fallback built on the
   existing `fallbackDescription`. Done when: works with Foundation unavailable (rules) and available (model), with
   tests for both through a fake provider.
2. **Codeplug review.** A "Review" button in `CodeplugView` runs `CodeplugValidator` (exists, deterministic), then asks
   the provider to explain the findings in plain language. Fixes are offered only where `CodeplugEditing` can apply
   them deterministically, shown as a diff before applying. The AI never edits a codeplug itself.
3. **Aviation briefing.** A "Brief me" button in Air Data turns `AviationPicture` and decoded METAR/TAF into a short
   digest. The deterministic digest (counts, farthest aircraft, emergency squawks 7500/7600/7700, worst weather) ships
   first and is useful without any model.
4. **Session log, then report.** Persist session events (scanner hits, saved channels, decoder messages, aircraft,
   weather) in `UserDatabase`; "Generate report" produces Markdown, exportable. PCC only on explicit choice.
5. **MLX runtime and local assistant.** Link an MLX Swift LLM package, implement `MLXProvider` over
   `ModelLibrary`'s installed models, add a chat tab grounded in bundled docs (workshop catalog, decoder recipes).
   Memory guard: on 18 GB, default to 1B/3B 4-bit; refuse 12B. Only the owner's Mac can verify this (Metal).
6. **Signal ID.** Ship a rules-based classifier from bandwidth and spectral shape first (real, immediate, on the
   Scanner), and give the Core ML model a training pipeline under `script/` with a dataset plan. Until the package
   exists, do not count it as available.
7. **Semantic FCC search.** Start with full-text search in the pack SQLite (FTS5: licensee, service, county), then
   on-device embeddings (`NLContextualEmbedding`) if FTS is not enough. Wire into the Search panel.

**UI for AI Lab itself:** collapse the Feature Map to a compact list (status dot, one line, **Try it** button that
opens the matching tool); make the gauge count *invocable* features; fix the clipped chips; move "Implementation Path"
into docs; keep the MLX manager (it works) under a "Models" section.

## 8. Working in a cloud session (read before starting)

- **The cloud environment cannot run this app.** It needs macOS 27, IOUSBHost, AppKit and an attached dongle. CI
  (`.github/workflows/ci.yml`) builds and tests on a hosted macOS runner; its `apps` and `project` jobs are
  `continue-on-error`, so read their logs, not just the check colour.
- So: put logic in `SignalHiveCore` with Swift Testing tests, keep views thin, and rely on CI to compile the views.
  New app source files must be registered in the committed project: run `python3 script/register_app_sources.py`
  (CI checks it), or `xcodegen generate`.
- Every change that needs the owner's Mac (dongle, Foundation Models availability, MLX inference, audio) goes on an
  **owner QA checklist** in `docs/PROJECT_STATUS.md` instead of being claimed as verified.
- Two `.searchable` modifiers in one window crash the macOS app (section 2). One per window.
- Hardware tests (`RTLSDRHardwareTests`) need the dongle free; skip them: `swift test --skip RTLSDRHardwareTests`.
